# 响应延迟分析

测量用户首次看到有效响应的速度。

## 建立边界

1. 如果 `start_marker` 和 `end_marker`/`response_marker` 解析为唯一的应用 Slice 对，则使用它们作为应用定义的响应区间，并保留该指标定义。
2. 否则，识别用户输入事件及其分发到目标应用的过程。当显式边界缺失时，`inspect_problem_window_candidates` 可以在单操作假设下提供最后输入点加上问题持续时间回退方案。
3. 识别第一个可见地反映请求操作的呈现帧。
4. 使用场景标记或显式业务上下文来决定什么算作有效反馈。
5. 不要仅仅因为后续帧容易定位就用它替代响应帧。

## 分析

1. 测量输入到首有效帧的延迟。
2. 在数据可用时，分解输入分发、应用处理、UI 状态更新、渲染准备和帧呈现。
3. 测试 CPU 执行、调度、锁、IPC、同步 I/O、任务队列和渲染作为候选原因。
4. 使用相同的输入和视觉响应语义与基线比较。

## 输出要求

- 报告输入和首响应边界及证据 ID。
- 描述为什么选定的帧是有效反馈。
- 不要在响应边界处声称整个操作已完成。
- 如果无法证明有效响应帧，记录限制并避免确认的根因。
