# 帧卡顿分析

根据实际显示节奏分析帧性能。

## 确定范围

1. 使用场景边界规则识别目标应用和有限的分析区间。当已证明存在更小的问题区间时，不要使用整个 Trace。
2. 识别应用帧生产流水线。在没有帧或栈证据的情况下，永远不要将 OS 进程主线程等同于 UI 线程。
3. 在知道目标 ipid 和区间后调用 `inspect_frame_jank`。首先使用 `frame_producer_itid=0`。当存在多个生产者时，仅在有框架、帧所有权或应用证据的情况下选择另一个候选。
4. 使用工具返回的刷新率或 VSync 周期。永远不要假设 60 Hz。当观察到动态刷新时，分别处理每个节奏段。
5. 区分应用实际帧、映射的 RenderService 呈现、预期槽位、慢帧、错过截止时间和丢弃的候选。不要仅凭较长的持续时间就声称呈现丢弃。

## 渲染架构

1. 将关键路径视为角色图，而非固定的主线程路径：输入/VSync → 框架 UI/JS/GUI → 布局/挂载 → 光栅化/渲染 → RenderService/UniRender → GPU/栅栏 → 呈现。
2. 在 Qt、Flutter、React Native、Compose Multiplatform/KMP 托管的 UI 和其他引擎中，UI 工作可能不在主线程上。框架检测仅在有线程名加切片/调用栈或帧所有权支持时才是假设。仅 KMP 不能识别 UI 工具包。
3. 应用到 RenderService 的归属需要 `frame_maps`、VSync/帧链接或等效的平台关联。RenderService 是一个全局进程；其整个进程的 CPU 或 Perf 份额永远不属于目标应用。
4. 统一渲染仅由目标帧路径上的 UniRender/平台证据证明。一般的 RenderService 映射证明跨进程渲染，而非确切的统一渲染模式。
5. GPU 归属需要映射的 GPU 切片、队列或栅栏。否则报告 GPU 原因不可用。
6. 当 `frame_producer_ui_mismatch` 报告一个强有力佐证的框架 UI/绘制线程与 `frame_slice` 所有者不同时，将两个线程都保留在关键路径分析中。将帧所有者视为可能的平台/包装流水线，不要将其帧数或 FPS 作为目标 UI Surface 的最终 FPS。

## 指标

1. 为每个节奏段推导 `budget_ms = 1000 / refresh_rate_hz`。
2. 优先使用映射的呈现时间戳来计算有效 FPS。应用帧生产 FPS 是一个单独的指标，必须如此标注。
3. 在活跃渲染集群上计算有效 FPS。静态或大部分空闲的区间必须报告为无意义，而非低 FPS。
4. 报告实际帧数、映射呈现数、预期槽位数、慢帧数、卡顿帧数、错过 VSync 数、卡顿率、P50/P90/P95/P99/最大帧持续时间，以及当可用时的最严重连续卡顿集群。
5. 仅在没有最终呈现证据证明丢弃的情况下，将预期但无实际帧作为丢帧候选。

## 分析

1. 从最差的单个帧和集群开始。分析其精确窗口，而非将整个窗口的线程配置文件应用于每个帧。
2. `observable_delay_stage` 定位延迟的流水线阶段，但不是根因。将其与 Running、Runnable、睡眠、D 状态、优先级、CPU 分布、唤醒链、切片和目标线程 Perf 关联。
3. 对于应用执行过载，命名具体的应用切片或符号。通用事件循环、框架包装器、HAP+偏移聚合和模块名称是上下文而非优化目标。
4. 对于调度不足，证明 Runnable 延迟和相关的竞争工作。对于阻塞，在数据允许时识别等待和唤醒者。对于 I/O，引用确切的 D 状态或同步操作。
5. 对于 RenderService 延迟，仅使用目标帧的映射 RS 线程和区间。区分继承的延迟提交和 RS 执行超预算。
6. 仅使用 Bottom-up Perf 来细化 Top-down 目标帧路径。将 Perf 范围限定为选定的应用生产者/框架渲染线程和映射的 RS 线程。
7. 仅在具有相同区间语义、目标流水线和节奏的情况下比较基线。

## 建议

1. 将每条建议与已证明的原因和具体操作联系起来。
2. 应用工作：拆分、延迟、缓存或移动命名的关键路径工作。
3. 可运行/调度：减少命名的竞争工作，或纠正已证明的优先级/核心分布问题；不要泛泛地推荐亲和性。
4. 等待/I/O：移除命名的同步依赖、预取、批处理或缩短已证明的锁/IPC 链。
5. RenderService/UniRender：仅当目标帧渲染证据支持时，推荐图层、过度绘制、效果、纹理或合成更改。
6. GPU：仅在有 GPU 证据时推荐着色器/纹理/渲染目标更改。
7. 包含验证指标，如有效 FPS、错过 VSync 数、卡顿率、P95 持续时间或最差集群持续时间。

## 输出要求

- 引用选定的生产者流水线、刷新/节奏来源、帧预算、受影响的区间、坏帧/集群标识符和证据 ID。
- 当有效 FPS、Surface 标识、统一渲染模式、最终呈现或 GPU 原因不可用时，明确声明。
- 不要仅用平均 FPS 来否定孤立但可见的卡顿。
- 当帧事件、目标流水线或有效区间不可用时，停止而不给出帧发现。
